# RateDeed — UI/Design-Quality Audit (enterprise marketplace-Jealous Lens)

**Date:** 2026-08-13
**Scope:** Both web (ratedeed) and mobile (ratedeedmobile) — contractor dashboard and homeowner flows. Assessed from code: hierarchy, consistency, state design, typography, motion, dark mode, accessibility, density, platform conventions, empty states.
**Status:** ✅ VERIFIED — 36 of 37 findings survived adversarial verification (verifiers confirmed the factual basis in code).

## Summary

- **Total confirmed:** 36 (36 confirmed / 1 refuted)
- **Severity:** 8 high · 27 medium · 1 low

## The core problem (one sentence)

The product has **three parallel design systems** — a JS token object, a dead shadcn CSS-variable layer that nothing reads, and ~1,300 hardcoded hex values hand-rolled in screens — so the UI can never read as one cohesive product, and dark mode is broken across nearly every shared primitive.

## The fix priority (biggest leverage first)

1. **Converge the design system** — one source of truth (designTokens.js), wire or delete the dead HSL-var layer, ban raw hex and arbitrary Tailwind classes.
2. **Fix dark mode in the primitives** — Card/Modal/BottomSheet/Input/Skeleton/Badge/Tabs/Toast currently hardcode light surfaces; in dark mode they glare white against near-black screens.
3. **Enforce a type scale** — stop 8px captions and text-[Npx] sprawl; make the Typography token the only source.
4. **One currency formatter + one primary button color** across every money screen and flow.
5. **Designed states everywhere** — replace naked spinners and bare grey empty text with skeletons and empty-state components; error states that offer retry instead of "Not found".
6. **Accessibility floor** — 44px+ touch targets and labels on icon-only controls.
